## Why this matters

`Backend::clipsList()` builds a fresh list of maps (about 35 keys per clip plus an 80-value
waveform) every time QML reads the `clipsList` property. Seven places read it, and each re-reads it
whenever `timelineChanged` fires, which happens on every edit, every tick of an inspector slider
and every keystroke in a title. So one slider tick builds the whole list seven times: three times
for the three timeline lanes, once for the viewer, and three times for the export dialog, which
also recomputes its size estimate although it is closed. After this plan the list is built once per
change, places that only need "is it empty" read a count, and the export estimate is computed only
while the dialog is open.

This plan deliberately does not replace the list with a row-level model; see Maintenance notes.

## Steps

### Step 1: A counter the test can read, and cheap counts

`src/backend.h`:
- add `Q_PROPERTY(int clipCount READ clipCount NOTIFY timelineChanged)` and
  `Q_PROPERTY(int textCount READ textCount NOTIFY timelineChanged)` next to `clipsList`;
- add public methods `int clipCount() const;`, `int textCount() const;` and
  `int clipsListBuilds() const { return m_clipsListBuilds; }` with the comment
  `// How often the clip list was rebuilt; tests use it to catch redundant QML reads.`;
- add the private member `mutable int m_clipsListBuilds = 0;`.

`src/backend.cpp`: define `clipCount()` as `return int(m_project.clips.size());`, `textCount()` as
`return int(m_project.texts.size());`, and add `++m_clipsListBuilds;` as the first line of
`clipsList()`.

### Step 2: Test first

Add a private slot `oneClipListBuildPerEdit` directly after `testUnsavedChangesGuard`. Copy that
test's window setup through `QVERIFY(QTest::qWaitForWindowExposed(window));`, import a 2.0 s sample
video, wait for imports, then:

```cpp
        QTest::qWait(300);
        QCOMPARE(backend.clipCount(), 1);
        const QString clipId = backend.selectedClipId();
        QVERIFY(!clipId.isEmpty());

        const int before = backend.clipsListBuilds();
        backend.updateClipProperty(clipId, "brightness", 0.2);
        QTest::qWait(200);
        const int builds = backend.clipsListBuilds() - before;
        QVERIFY2(builds >= 1, "the timeline did not refresh after the edit");
        QVERIFY2(builds <= 2, qPrintable(QString("one edit rebuilt the clip list %1 times").arg(builds)));
```

Do not call `backend.clipsList()` between `before` and `builds`; it would count.

**Verify (must FAIL now)**: build command → `0`, then full test command →
`FAIL!  : CutCapTests::oneClipListBuildPerEdit` with a message like
`one edit rebuilt the clip list 7 times` (any number above 2).

## Maintenance notes

- This removes repeated list builds, not delegate churn: each edit still resets the three lane
  Repeaters, destroying and recreating every clip delegate. The real fix is a `QAbstractListModel`
  with per-row `dataChanged`; it touches drag/trim code and about forty test call sites, and should
  wait until tests cover project open and a successful export.
- New QML that needs clips should read `root.clips` in `TimelinePanel.qml`, or a count.
