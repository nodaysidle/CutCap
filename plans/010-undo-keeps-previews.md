## Why this matters

CutCap's undo stack stores whole copies of the project. A media asset's thumbnail, filmstrip and
waveform are generated by a background job that finishes *after* the asset was added, so the copy
taken when the clip was placed holds an asset with no previews. Undo restores that copy: the bin
entry loses its thumbnail and clips lose their filmstrip and waveform until the project is
reopened. Previews are derived from the file, not something the user edited, so undo must not
discard them.

## Current state

All in `src/backend.cpp` (declarations in `src/backend.h`).

```cpp
void Backend::undo() {
    if (m_undoStack.isEmpty())
        return;
    m_undoMergeKey.clear();
    m_redoStack.append(m_project);
    m_project = m_undoStack.takeLast();
    pruneClipSelection();
    m_dirty = true;
    emit projectChanged();
    emit assetsChanged();
    emit timelineChanged();
    emit selectionChanged();
    emit previewChanged();
    setStatus("Undo");
}
```

`redo()` is the mirror image: `m_undoStack.append(m_project); m_project = m_redoStack.takeLast();`.

Previews arrive here (in `Backend::startPreviewJob`'s finished handler), written into the live
project only:

```cpp
        m_project.assets[idx].thumbnailPath = prepared.thumbnailPath;
        m_project.assets[idx].filmstripPath = prepared.filmstripPath;
        m_project.assets[idx].waveformPeaks = prepared.waveformPeaks;
```

`m_project` is a `Project`; `Project::assets` is a list of `MediaAsset` with fields `id`,
`thumbnailPath`, `filmstripPath`, `waveformPeaks` (a `QVector<double>`); `Project::findAssetIndex(id)`
returns the index or -1. `void startPreviewJob(const MediaAsset &asset);` is a private member of
`Backend`.

Import flow, for the test: `importSingleMedia(path)` probes the file in a job, adds the asset, places
a clip (this takes the undo snapshot), then a second job prepares the previews.
`waitForImports(b)` in the tests waits for both jobs.

### Step 2: Carry previews across a snapshot swap

Declare in `src/backend.h`, next to `startPreviewJob`:

```cpp
    void carryPreviewsFrom(const Project &previous);
```

Define in `src/backend.cpp`, directly above `Backend::undo()`:

```cpp
// A snapshot taken before an asset's previews arrived holds none. They are derived from the file,
// so after swapping snapshots they are copied from the state just left, or regenerated.
void Backend::carryPreviewsFrom(const Project &previous) {
    for (MediaAsset &asset : m_project.assets) {
        const bool missing = asset.thumbnailPath.isEmpty() && asset.filmstripPath.isEmpty() &&
                             asset.waveformPeaks.isEmpty();
        if (!missing)
            continue;
        const int idx = previous.findAssetIndex(asset.id);
        if (idx >= 0 && !(previous.assets[idx].thumbnailPath.isEmpty() && previous.assets[idx].filmstripPath.isEmpty() &&
                          previous.assets[idx].waveformPeaks.isEmpty())) {
            asset.thumbnailPath = previous.assets[idx].thumbnailPath;
            asset.filmstripPath = previous.assets[idx].filmstripPath;
            asset.waveformPeaks = previous.assets[idx].waveformPeaks;
        } else {
            startPreviewJob(asset);
        }
    }
}
```

In `undo()`: keep a copy of the state being left and call the helper right after the swap:

```cpp
    const Project left = m_project;
    m_redoStack.append(m_project);
    m_project = m_undoStack.takeLast();
    carryPreviewsFrom(left);
```

Do the same in `redo()` (`const Project left = m_project;` before the append, `carryPreviewsFrom(left);`
after `m_project = m_redoStack.takeLast();`).

If `findAssetIndex` is not `const` in `src/project.h`, that is a STOP condition (do not edit
`project.h`).
