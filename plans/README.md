# Implementation Plans

Generated by the improve skill on 2026-11-20 from an audit of CutCap at `bb813a0` plus the then
uncommitted working tree (snapshot commit `733897d` on branch `advisor/audit-fixes`). Target system:
Arch Linux, Omarchy 4.5, Hyprland 0.56 scrolling layout, one 2560×1440 monitor at scale 1.

The owner asked for every finding to be fixed, so all of them were planned (no selection step).
Executors are Haiku subagents, run one at a time on the branch; the reviewer keeps this index.

## Dependency notes

- 006 requires 001 because it isolates the data directory 001 introduces.
- 007 requires 006 because its layout test relies on the window-size assertion and the
  zero-area button check 006 adds.
- 008 requires 002 because it extends the `modalOpen` rule 002 adds.
- 015 requires 004 (absolute paths survive the round trip), 006 (isolated cache and data
  directories) and 011 (the CLI refuses an image on the audio track).
- All plans add test slots to the single file `tests/cutcap_tests.cpp`, so they run one at a time.

## Findings considered and rejected

- Per-playhead-tick lane map rebuilds (`src/backend.cpp` `refreshLanes`): microseconds at current
  clip counts; not worth a plan until the clip model work lands.
- Moving the preview look pipeline to a shader: multi-day; only the visibility gate is planned.
- A row-level clip model (`QAbstractListModel`) to stop delegate churn on every edit: the right fix
  for the remaining cost after plan 014, deferred until plan 015's open and export tests exist.
- Text-to-speech text starting with `-` being read as an espeak option: espeak is not installed on
  the target machine and the behaviour was not reproduced.
- Splitting the 580-line `uiSmokeButtonsPipAndDrop` test: wanted, deferred as its own job.
